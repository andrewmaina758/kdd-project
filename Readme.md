# KDD Project: Student to Job Matching

## Project Overview

This project builds a data-driven pipeline for matching students to relevant job opportunities.
The workflow combines:

- job postings preprocessing,
- student profile preprocessing,
- semantic text embeddings using BERT,
- similarity-based retrieval of top career matches,
- location-aware ranking support,
- and statistical validation of student dataset quality.

The implementation is notebook-first and organized into three stages:

1. data cleaning and preparation,
2. modelling and match generation,
3. validation of dataset realism and consistency.

## Data Sources

The project uses the following local datasets:

- `data/postings.csv`: job postings data.
- `data/student_data.csv`: student records (degree, school year, skills, experience, location interest, etc.).
- `data/uszips.csv`: ZIP-to-city/state mapping used for location enrichment.
- `data/jobs_sample.csv`: sampled cleaned jobs generated by the pipeline.

## Pipeline Summary

### 1) Data Cleaning (`data_cleaning.ipynb`)

Key operations:

- Loads selected posting fields (`job_id`, `title`, `description`, `location`, `zip_code`, `fips`, and others).
- Normalizes text columns to lowercase and strips whitespace.
- Preserves ZIP/FIPS as strings to keep leading zeros.
- Removes low-quality location rows (for example, generic location with missing ZIP/FIPS).
- Enriches posting location using `uszips.csv` and extracts state where possible.
- Cleans student fields and normalizes skill strings.
- Builds text features for students and jobs.
- Includes both legacy TF-IDF and BERT-based vectorization code, with BERT used for the current matching workflow.

### 2) Modelling (`modelling.ipynb`)

Key operations:

- Repeats core cleaning steps for modelling reproducibility.
- Samples the cleaned jobs dataset and writes `data/jobs_sample.csv`.
- Loads student data and prepares composite student text from:
	- major,
	- skill,
	- area of experience,
	- school year,
	- degree.
- Builds job text from title + description.
- Uses spaCy title normalization to improve grouping consistency.
- Encodes jobs and students with `sentence-transformers/all-MiniLM-L6-v2`.
- Computes cosine similarity between student and job vectors.
- Retrieves top-K job matches per student.
- Aggregates normalized matched titles and computes a combined relevance score.
- Adds location-interest alignment by comparing preferred student location against top-demand states per title.

### 3) Validation (`skill_validation.ipynb`)

Validation notebook applies quality and realism checks to `data/student_data.csv`, including:

- structural validity rules:
	- degree-school-year consistency,
	- GPA range checks,
	- non-negative experience checks,
- contradiction rate estimation and confidence interval,
- monotonic academic progression test (Spearman correlation between school-year order and experience),
- association tests (for example, chi-square/Cramer's V for categorical dependencies).

## Core Matching Method

At a high level, matching is based on semantic similarity:

$$
	ext{similarity}(s, j) = \cos\left(\mathbf{e}_s, \mathbf{e}_j\right)
$$

where:

- $\mathbf{e}_s$ is the embedding of a student profile text,
- $\mathbf{e}_j$ is the embedding of a job text.

For each student, top-$k$ jobs are selected by descending cosine similarity, then title-level scores are aggregated for recommendation output.
